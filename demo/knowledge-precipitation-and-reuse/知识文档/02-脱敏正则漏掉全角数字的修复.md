## Context

医院客服 Agent 会在把用户文本发给外部模型前做脱敏（`service.py` 的 `_redact`），并复用同一套号码识别规则在 `answer()` 中定位患者。联调评审（人工提出）报告：患者把手机号打成全角数字 `１３９００００１２３４` 时，原文会原样出现在发给外部模型的请求里；带空格（`139 0000 1234`）和短横（`139-0000-1234`）的写法则已被脱敏。约定禁传字段为"患者完整手机号、完整证件号"，全角写法表达同一号码，同样必须拦住。

## Solution

直接观察原始代码可见，`service.py` 的识别正则为 `(?<![0-9])(?:(?:[0-9][ -]?){17}[0-9Xx]|1(?:[ -]?[0-9]){10})(?![0-9])`，字符类里只有半角 `[0-9]` 与半角分隔符，因此全角数字（不同 Unicode 码点）根本匹配不到。

本次改动（经工具结果确认）：

- 在识别正则的字符类中加入全角范围：`[0-9０-９]`，前后负向断言同样加入 `０-９`，并补入全角分隔符 `　`、`－`。
- 新增宽度归一化表 `IDENTIFIER_WIDTH = str.maketrans("０１２３４５６７８９Ｘｘ　－", "0123456789Xx -")`，在 `_identifier_value` 中先 `translate` 再比较/掩码。
- 由于查找患者与脱敏共用 `IDENTIFIER` / `_identifier_value`，两条路径同时获得全角支持。

回归用例 `test_identifier_variants_are_redacted_in_both_model_requests` 覆盖 `139 0000 1234`、`139-0000-1234`、`１３９００００１２３４`、混排 `１３9－0000　１２３４` 以及全角/混排证件号，逐条检查"工具选择"和"工具结果回填"两次请求的本地载荷不含原始号码、且载荷中为掩码形式。

测试证据：新用例在修复前运行出现 4 项失败（全角写法仍出现在载荷中）；修复后 `python3 -m unittest discover` 显示 "Ran 13 tests … OK"，`git status --short` 显示 `M service.py`、`M tests/test_appointments.py`。

## Lessons

- 正则脱敏的字符类要显式纳入 Unicode 全角范围，或先做宽度归一化再匹配；只看半角 `[0-9]` 会漏掉全角数字，而它们表达的是同一个敏感号码。
- 查找（患者定位）与脱敏复用同一段识别/归一化代码，能避免"一处改了、另一处还漏"的不一致。
- 回归用例要覆盖全角、全半角混排以及空格/短横等分隔符变体，并断言"发给模型的真实载荷"，而不是只看对用户的返回值。
- 归一化只用于比较与掩码，不要破坏查询本身：全角证件号仍应能查到对应患者。
