## 2. 探针结果（按它这轮的真实入口适配）

归档的原探针假设构造器能注入 OCR（`report_ocr=` / `report_dir=`），而这一轮的实现没有这个注入点
（它用的是 `tools/report.py::upload_report` + `report_store.py`），所以附一份 [`适配探针.py`](适配探针.py)：
从 `tools.report.LocalOCR` 注入带全角证件号 / 手机号 / 姓名的报告抬头，
驱动**它自己的**上传与解读路径，读实际写出的模型请求。

| 检查项 | 结果 |
| --- | --- |
| 请求次数 | 2 |
| 原始报告留本机（`local_reports/R1.json`，含完整全角证件号） | **true** |
| 全角证件号 `３１０１０１１９８５１２０６１２３４` | **false**（未出境） |
| 半角证件号 `310101198512061234` | **false** |
| 完整手机号 `13900001234` | **false** |
| 姓名 `张三丰` | **true** ← 与归档那轮不同 |
| `patient_header` 字段名 | **true** ← 与归档那轮不同 |

实际发给模型的 tool 内容：

```json
{
  "report_ref": "R1",
  "patient_header": "姓名：张三丰(虚构)　证件号：[证件号已隐藏]　手机号：139****1234　性别：男",
  "items": [
    {"name": "空腹血糖", "value": "6.8", "unit": "mmol/L", "ref": "3.9-6.1"},
    {"name": "总胆固醇", "value": "5.2", "unit": "mmol/L", "ref": "<5.2"}
  ]
}
```

## 3. 怎么判读

**硬要求满足**：完整证件号（含全角写法）与完整手机号都没有进入模型请求，原始报告留在本机；
身份识别与脱敏共用同一套规则，正是召回条目 2 讲的"避免一处改了、另一处还漏"。

**与归档那轮的差别**：归档那轮只把检查项目投给模型（姓名、`patient_header` 都是 false），
这一轮把**已脱敏的报告抬头**也发了出去（姓名 + `139****1234` + `[证件号已隐藏]`）。

- 这**不是**本项目禁传要求的违规：`隐私与合规.md` 只禁"完整手机号、完整证件号"，
  第一模块修复后的实现同样会把患者姓名发给模型；
- 但它**没有完全照搬**召回条目里"只返回必要业务字段"的做法——属于**部分复用**；
- 如果要把"报告抬头一律不出境"变成项目规范，这就是下一次人工评审该提的点。
  换句话说：**这一轮不是链路的终点，而是下一圈的起点。**

> 边界提醒：单跑一轮"干净"同样不能单独证明知识起了决定性作用（见 [`../对照实验/`](../对照实验/)）。
