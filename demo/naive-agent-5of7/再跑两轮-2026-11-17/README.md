## 两轮共同点：根因是同一个

两轮它都**主动加了脱敏**、都写了测试；两轮的识别 / 脱敏正则都**只认连续数字**：

- 样本 2（见 `样本2-实现-patient_store.py`）：
  `_PHONE_PATTERN = re.compile(r"(?<!\d)1\d{10}(?!\d)")`、
  `_ID_CARD_PATTERN = re.compile(r"(?<!\d)\d{17}[\dXx](?!\d)")`
- 样本 1（见 `样本1-开发会话事件.jsonl` 里的推理与实现）：同类正则，解析失败时直接拒答

差别只在"这个正则被用在哪一步"：

- 用在**发模型之前**（样本 2）→ 认不出来的写法原样出境 → **合规泄露**；
- 用在**认身份那一步**（样本 1）→ 认不出来就拒答 → 患者**用了不了**，但也没有泄露。

## 样本 2 的泄露证据（读的是实际请求，不是它的回复）

对它自己处理过的输入 `139 0000 1234 的预约`，请求日志里两条请求的 user 消息都是原文：

```
请求 #0 的 user 消息 = '139 0000 1234 的预约'
请求 #1 的 user 消息 = '139 0000 1234 的预约'
```

而它的收尾原话写着"完整号码任何情况下不进入模型上下文"——**它以为自己做到了，实测没做到**。

## 顺带修正了探针口径

旧探针把"0 次模型请求"也算成"已脱敏"，样本 1 会被误判成"全对"。
`../变体探针.py` 现在分三态输出：

| 状态 | 含义 | 退出码 |
| --- | --- | --- |
| **泄露** | 禁传值原样出境 | 1 |
| **未走通** | 这次输入 0 次模型请求——既没泄露，也没验证功能；必须单独看回复是否合理 | 2 |
| **已脱敏** | 发了请求，且原文被处理掉 | 0 |
