# 演示目录

这里放两段可以现场跑的演示材料，合起来是案例的**完整链路**。

| 目录 | 演示什么 | 关键结果 |
| --- | --- | --- |
| [`naive-agent-5of7/`](naive-agent-5of7/README.md) | **前半段**：裸 Agent + 一句需求交给开发 AI，复现"开发 AI 自己写出脱敏覆盖不全" | 用 `tencent-cloud/deepseek-v4.1-flash` 复测：**漏 5/7**，与原始第 6、7 次一致 |
| [`knowledge-precipitation-and-reuse/`](knowledge-precipitation-and-reuse/README.md) | **后半段**：人工纠正 → 知识沉淀 → 召回 → 第二模块（报告解读）复用 | 召回 2 篇知识文档；第二模块独立探针：模型请求里身份字段**全部 false** |

## 一句话演示脚本

1. **前半段**：把仓库根的 [`agent/`](../agent/) 复制成工作副本，交给一段全新会话，贴 `起始任务.md` 的原文 →
   跑 `变体探针.py`，报出 5/7 泄露 → 这就是"开发 AI 自己写出来的缺陷"。
2. **后半段**：人工评审指出问题 → 修复 → FormSy 采集/提炼出
   `knowledge-precipitation-and-reuse/知识文档/` 那两份 → 新会话做第二个模块（报告解读），
   把召回结果交给它 → 独立探针验证实际模型请求里没有身份字段。

## 边界（别讲过头）

- 前半段是**概率性**的：同条件四次里三次出现缺陷、一次全拦；每次漏的写法集合也不同。
- 后半段"第二个模块干净"**不能单独证明知识起了作用**——那个模块的设计本身就把报告抬头挡在模型外面，
  3+3 对照两组都干净。知识有效性的硬证据是强诱导场景的 8 对 8：**给知识 0/8 泄露、不给知识 8/8 泄露**。
- 前半段那次开发 AI **自己发现了仓库里的合规冲突**（推理原文见
  [`预检问题回应.md`](预检问题回应.md) 第 0 节），它也确实加了脱敏，只是**只认连续数字写法**。
  所以讲法要落在"**做了但没做全**"，不要讲成"AI 完全没想到要脱敏"。

仓库内患者、手机号、证件号全部为**虚构合成数据**，不连接任何真实医院系统。

## 演示前检查清单

按顺序过一遍，四件事都能省掉现场翻车：

1. **日期**：从仓库根的 [`agent/`](../agent/) 复制出工作副本后，跑一次
   `python3 naive-agent-5of7/演示日期准备.py <工作副本>`（夹具日期写死在 2026-11-17/18，11-18 之后"明天"就空了）。
2. **别把本仓库带上演示机**：演示起点是 `agent/`（实测 7/7 全泄露），但**本仓库本身带着答案**——
   `demo/` 里有修复后的做法与知识文档，git 历史里还有那次修复提交。
   `-s workspace-write` 只限制写、不限制读，所以演示机上只留 `agent/` 复制出的工作副本，
   不要把本仓库 clone 到工作区旁边。
3. **模型通道**：前半段要用 `tencent-cloud/deepseek-v4.1-flash`（经本机 magpie 桥）跑，
   并确认 magpie 在 `127.0.0.1:3425` 监听；换模型会改变结果分布。
4. **重跑预算**：缺陷是概率性的（同条件四次里三次出现）。现场若一次没复现，用
   `naive-agent-5of7/历史结果/` 与 `本次复测/` 说明分布，或当场重跑一轮。
