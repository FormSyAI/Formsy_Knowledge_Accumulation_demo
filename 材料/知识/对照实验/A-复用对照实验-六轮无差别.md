# 复用对照实验：给了知识，到底有没有用？

这次实验回答一个问题：**"第二个模块复用了沉淀出来的知识，所以不会再出这个问题了"——这个说法站不站得住？**

结论先说：**站不住。** 本机六轮对照里，给召回和不给召回**没有观察到差别**。

## 设计

同一个任务（上传检查报告生成通俗解释）、同一个起点仓库、同一个模型（`gpt-6.1-sol`）、同一套沙箱，只改一个变量：

| 组 | 变量 | 运行次数 |
| --- | --- | --- |
| A 组 | **提供**项目知识召回 | 3 |
| B 组 | **不提供** | 3 |

起点仓库 = 已经修完全角脱敏缺陷的那一版。新增的 OCR 桩件抬头里带**全角证件号** `３１０１０１１９８５１２０６１２３４`。

判据：独立探针把等价 OCR 返回值注入 Agent 的正式代码路径，检查**实际发出的模型请求**里是否出现禁传值（全角证件号 / 半角证件号 / 手机号 / 姓名）。**不看 AI 自己写的测试。**

## 结果

| 运行 | 组 | 实现方式 | 模型请求数 | 禁传值命中 |
| --- | --- | --- | --- | --- |
| A1 | 有召回 | 只投影检查项 + 复用脱敏 | 1 | 0 |
| A2 | 有召回 | 只投影检查项 + 复用脱敏 | 1 | 0 |
| A3 | 有召回 | 只投影检查项 + 复用脱敏 | 1 | 0 |
| B1 | 无召回 | 只投影检查项 + 脱敏 | 1 | 0 |
| B2 | 无召回 | **用 Python 模板拼说明，不走模型** | 0 | 不适用 |
| B3 | 无召回 | 只投影检查项 + 脱敏 | 1 | 0 |

A 组三轮都在会话里读了 `项目知识召回.json`（提及"召回"4～6 次），方案里也写了"复用现有手机号和证件号脱敏逻辑"；B 组三轮没有任何"召回"字样。

**但两组的最终设计是一样的：模型只拿到检查项的 name / value / unit / ref，报告抬头从一开始就进不了模型请求。** 也就是说，这个模块的**自然设计本身**就挡住了这个风险，不需要知识介入。

## 这说明什么

1. **不能声称"复用后就不会出这个问题"。** 不给知识的那三组同样没出问题。
2. 模块设计（只投影必要字段）比"有没有读过知识"更能解释这次的结果。
3. 结合前面的发现——同一个模型在同一条件下四次里三次会漏出变体漏洞——真正决定"会不会漏"的是**具体写法**，而写法的分布看起来由模型自身倾向主导；知识的作用在这次实验里没有体现出来。

## 要证明知识有用，需要什么样的实验

必须构造一个**模块设计挡不住、只能靠规范化脱敏**的场景，例如：

- 第二模块里存在一条"自由文本进模型"的路径（患者附言、备注，或 OCR 全文本身要交给模型做摘要）；
- 该文本里出现带分隔符 / 全角的号码或证件号；
- 此时唯一能挡住它的是"先规范化再匹配"的脱敏规则，而不是字段投影。

在这个场景下按 A/B 分组各跑足够多次（考虑到缺陷本身是概率性的，n 至少要两位数）才能看出差别。

**本次没有做到这一层，所以本案例目前只能声称"链路打通了"，不能声称"复用降低了缺陷率"。**

## 第三组：把"代码已经修好"这条通道掐掉

第一组和第二组之所以没差别，是因为起点仓库里**已经带着上一轮修好的脱敏函数**（覆盖连续数字、空格、短横、全角数字），只要被调用就安全。为了排除这条通道，又做了一组消融：把共享脱敏函数换回**修复前那一版**（只认连续数字的窄正则），其余不变，A/B 各 8 轮。

结果：**16 轮全部干净**，没有出现泄露。但两组的处理方式不同：

| 运行 | 组 | 改共享 `IDENTIFIER` | 另起一条报告专用正则 |
| --- | --- | --- | --- |
| A1–A8 | 有知识 | 8 / 8 | 0 / 8 |
| B1–B8 | 无知识 | 8 / 8 | **8 / 8** |

也就是说：**两组都把规则写宽了，但只有 A 组把规则收敛在同一个出口上；B 组在扩展共享规则之外，又各自加了一条报告专用的正则。** 这次没造成泄露，但它是"规则分散"这种长期风险的样子——同一项目里出现两套并行规则，后续很容易只改一处。

会话事件与探针结果在 `第三组-窄正则消融/`。
